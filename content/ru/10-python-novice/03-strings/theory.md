# Теория · Строка не меняется, она отвечает новой

На прошлом уровне текст и число оказались разными вещами, и `int()` со
`str()` переводили значение с одной стороны на другую. Здесь мы остаёмся
внутри текста и разбираем главное его свойство: **строку нельзя изменить**.
Всё, что похоже на изменение, на самом деле выдаёт новую строку — и если её
не поймать, работа пропадает молча.

Это самая частая причина, по которой у новичка «код правильный, а ответ
старый».

---

## Метод — это функция, привязанная к значению

Раньше функции вызывались отдельно: `int(miles)`, `str(total)`, `len(text)`.
Имя, скобки, аргумент внутри.

У строк есть второй способ вызова — через точку:

```python
text.upper()
```

Читается справа налево от точки: «возьми `text` и попроси у него `upper`».
Такая функция называется **методом**. Разница с `int()` только в записи: то
значение, над которым работают, стоит не в скобках, а перед точкой.

Части записи:

```python
text  .  upper  (  )
 │       │       └── скобки: вызвать. Без них вызова не будет
 │       └────────── имя метода
 └────────────────── значение, у которого метод спрашивают
```

**Зачем так.** Методов у строки десятки, и все они относятся именно к тексту.
Держать их отдельными именами (`upper(text)`, `strip(text)`, `replace(...)`)
значило бы занять эти слова на весь язык. Точка привязывает метод к типу
значения: у строки свой `upper`, у списка своего `upper` нет вовсе.

**Чего делать не надо.** Не забывайте скобки.

```python
text.upper      # это сам метод, как предмет
text.upper()    # это его вызов, и вот он даёт строку
```

Первая строка ничего не считает. Она вернёт что-то вроде
`<built-in method upper of str object at 0x...>` — сам метод, не результат.
Если попробовать взять от него срез, Python скажет:
`TypeError: 'builtin_function_or_method' object is not subscriptable`.

## Главный факт уровня: строку нельзя изменить

В Python строка **неизменяема**. Ни один метод не правит её на месте.

```python
label = "dallas"
label.upper()
print(label)      # dallas — как было
```

Метод отработал. Он даже посчитал результат — `"DALLAS"`. Но результат никуда
не положили, и он исчез в ту же секунду. `label` при этом не изменился и не
мог измениться.

Правильно так:

```python
label = "dallas"
loud = label.upper()
print(loud)       # DALLAS
print(label)      # dallas — исходник по-прежнему цел
```

Теперь строк две. Первая осталась прежней, вторая — новая.

Можно положить результат обратно в то же имя, тогда старое значение просто
некому будет искать:

```python
label = "dallas"
label = label.upper()
print(label)      # DALLAS
```

Оба варианта верные. Второй короче, первый нагляднее, когда исходник ещё
понадобится, — а в задании этого уровня он как раз не понадобится.

**Почему в языке сделали именно так.** Неизменяемая строка безопасна: если вы
передали её в чужую функцию, она не сможет испортить ваше значение. Ещё это
позволяет Python хранить одинаковые строки один раз и быстро использовать их
как ключи словарей — это пригодится на уровне про словари.

**Как это запомнить.** Метод строки — не приказ, а вопрос. Вы не говорите
«стань заглавной», вы спрашиваете «а как ты выглядишь заглавной?». Ответ надо
куда-то записать, иначе вы просто спросили и ушли.

## Уборка краёв: `.strip()`

```python
"  dallas run 47 ".strip()     # "dallas run 47"
```

`.strip()` возвращает новую строку, у которой с обоих краёв убрано всё
**пробельное**. Это не только пробел:

| Что | Как выглядит в коде | Откуда берётся |
|---|---|---|
| пробел | `" "` | лишние нажатия, копирование из таблицы |
| табуляция | `"\t"` | выгрузка из Excel и CSV |
| перевод строки | `"\n"` | чтение файла построчно, вставка из письма |
| возврат каретки | `"\r"` | файлы, пришедшие из Windows |

Все четыре невидимы на экране, и именно поэтому ошибки с ними такие
неприятные: строки выглядят одинаково, а не равны.

```python
"dallas" == "dallas "     # False, хотя на глаз одно и то же
```

**Важно: `.strip()` трогает только края.** Внутри он ничего не убирает.

```python
"  el paso run 60  ".strip()   # "el paso run 60" — пробел между словами остался
```

Это ровно то, что нужно в задании: метку надо очистить снаружи, а слова внутри
оставить как есть.

**Соседи.** `.lstrip()` убирает только слева, `.rstrip()` — только справа.
Пригодятся, когда одна сторона значима.

**Чего делать не надо.** Не пытайтесь убрать пробелы «вручную» через срез
вроде `text[2:-1]`: у разных меток разное число пробелов, и такой срез или
не дочистит, или откусит буквы.

## Регистр: `.upper()`, `.lower()` и соседи

```python
"dallas run 47".upper()        # "DALLAS RUN 47"
"DALLAS RUN 47".lower()        # "dallas run 47"
"dallas run 47".title()        # "Dallas Run 47"  — каждое слово с большой
"dallas run 47".capitalize()   # "Dallas run 47"  — только первая буква
```

Цифры и знаки регистра не имеют, поэтому `47` во всех вариантах остаётся `47`.

**Зачем это в работе.** Одна и та же метка приходит с доски то заглавными, то
строчными. Пока её не привели к одному виду, сравнивать метки бессмысленно:
`"DAL47" == "dal47"` — это `False`.

**Чего делать не надо.** Не приводите к заглавным то, что должно остаться как
есть, — например имя человека или пароль. Приведение к одному регистру нужно
для сравнения и для кодов, а не «для красоты».

---

## Ещё один частый метод: `.replace()`

```python
"dallas run 47".replace(" ", "-")     # "dallas-run-47"
"dallas run 47".replace("run", "рейс")  # "dallas рейс 47"
```

Берёт что заменить и на что. Тоже возвращает новую строку и тоже ничего не
меняет в старой.

```python
label = "dallas run 47"
label.replace(" ", "")
print(label)          # dallas run 47 — ничего не произошло
```

Та же самая ловушка, что и с `.upper()`. Она одна на все строковые методы.

## Ловушка уровня: вызвали и не поймали

Вот заготовка этого уровня, целиком:

```python
def solve(text: str) -> str:
    text.strip()
    text.upper()
    return text[:3] + text[-2:]
```

Первые две строки выглядят как уборка. На самом деле они делают так:

1. Python считает `text.strip()` — получается новая чистая строка.
2. Никто её не забирает.
3. Строка выбрасывается.
4. То же со второй строкой.
5. В `return` идёт **исходный грязный** `text`.

Python при этом не ругается. С его точки зрения вы честно вычислили значение
и решили им не пользоваться — так тоже бывает, это не ошибка. Поэтому программа
работает, ничего не падает, а ответ неверный. Такие ошибки называют **тихими**,
и они дороже громких: громкая падает сразу и показывает строку, тихая доезжает
до заказчика.

**Как отличить рабочую строку от холостой.** У строки, которая что-то делает,
результат куда-то девается: он либо попадает в имя через `=`, либо уходит в
`return`, либо становится аргументом другого вызова. Если строка состоит из
одного вызова и результат никуда не идёт — почти всегда это ошибка.

```python
text.strip()            # холостая: результат некуда не пошёл
clean = text.strip()    # рабочая: результат в имени clean
return text.strip()     # рабочая: результат ушёл наружу
print(text.strip())     # рабочая: результат ушёл в print
```

Единственное исключение — методы, которые действительно меняют объект и
ничего не возвращают. У строк таких нет вовсе; у списков есть, и на уровне про
списки мы на них наткнёмся с другой стороны.

## Цепочка вызовов

Раз метод возвращает строку, у результата снова можно спросить метод:

```python
text.strip().upper()
```

Читается слева направо: взяли `text`, попросили `strip` — получили новую
строку, у неё попросили `upper` — получили ещё одну. Итог тот же, что и в две
строки:

```python
clean = text.strip()
code = clean.upper()
```

**Что выбрать.** Цепочка короче, две строки понятнее и их удобнее проверять по
частям: можно напечатать `clean` и увидеть, дошло ли до неё. В эталоне этого
уровня — две строки именно поэтому.

**Чего делать не надо.** Не растите цепочку до пяти-шести звеньев. Когда
что-то пойдёт не так, у вас не будет места, куда вставить `print`.

## Индекс и срез: как достать кусок строки

Строка — это ряд символов, у каждого свой номер. Номера начинаются с нуля.

```
строка:    O    M    A    3    3
индекс:    0    1    2    3    4
с конца:  -5   -4   -3   -2   -1
```

**Один символ — квадратные скобки с номером:**

```python
code = "OMA33"
code[0]      # "O"
code[2]      # "A"
code[-1]     # "3"  — последний
```

**Кусок — срез, два номера через двоеточие:**

```python
code[0:3]    # "OMA"  — с нулевого по третий, третий не включая
code[:3]     # "OMA"  — то же самое: пустое слева значит «с начала»
code[3:]     # "33"   — пустое справа значит «до конца»
code[-2:]    # "33"   — два последних
code[1:4]    # "MA3"
```

**Почему правая граница не включается.** Так длина куска считается вычитанием:
`code[0:3]` — это ровно `3 - 0 = 3` символа. И два соседних среза `code[:3]` и
`code[3:]` вместе дают всю строку без пропусков и повторов. Если бы правая
граница включалась, символ с номером 3 попал бы в оба.

**Отрицательные номера** считают с конца: `-1` последний, `-2` предпоследний.
`code[-2:]` — «начиная с предпоследнего и до конца», то есть два последних
символа. То же самое можно написать длиннее:

```python
code[len(code) - 2:]
```

`len(code)` — длина строки, здесь 5. Значит срез начинается с номера 3.
Оба варианта верны; `code[-2:]` короче и не ломается, если длина изменится.

**Важное отличие индекса от среза.** Одиночный индекс за пределами строки
падает, срез — нет:

```python
"OMA"[5]     # IndexError: string index out of range
"OMA"[:5]    # "OMA" — срез просто отдаёт сколько есть
```

Поэтому срез — безопасный способ взять «первые три», даже если строка короче.

## Что ломается и как это выглядит

| Что вы увидите | Что произошло | Что делать |
|---|---|---|
| ответ совпал только на одной метке | уборка сделана, но результат не пойман | положите его в имя через `=` |
| ответ строчными вместо заглавных | `.upper()` не применён или применён вхолостую | `code = clean.upper()` |
| в ответе видны пробелы по краям | `.strip()` не применён или применён вхолостую | `clean = text.strip()` |
| `TypeError: ... object is not subscriptable` | у метода забыли скобки: `text.strip[:3]` | `text.strip()[:3]` |
| `AttributeError: 'str' object has no attribute 'stip'` | опечатка в имени метода | проверьте написание |
| `TypeError: can only concatenate str` | к тексту прибавляют не текст | переведите через `str()` |
| `IndexError: string index out of range` | одиночный индекс за концом строки | возьмите срез вместо индекса |
| `вернулся текст: нет` | функция вернула не строку | склейка двух срезов даёт строку — проверьте `return` |

---

## Чего делать не надо в этой теме

- **Не ждите, что метод изменит строку.** `text.upper()` не меняет `text`
  никогда, ни при каких условиях. Ловите результат.
- **Не убирайте пробелы срезом.** `text[2:-1]` подойдёт ровно к одной метке
  и сломается на следующей.
- **Не пишите метод без скобок.** `text.strip` — это сам метод, а не строка.
- **Не сравнивайте метки, не приведя их к одному виду.** `" DAL47 "` и
  `"dal47"` — разные строки, пока их не почистить и не привести к регистру.
- **Не удлиняйте цепочку ради краткости.** Отладить `a.b().c().d().e()`
  сложнее, чем четыре именованные строки.

## Как это выглядит в настоящем коде

Почти любая обработка входных данных начинается ровно с этих двух шагов:

```python
def normalize(raw: str) -> str:
    """Привести пришедшую извне строку к виду, пригодному для сравнения."""
    clean = raw.strip()
    return clean.lower()


def known_city(raw: str, cities: list[str]) -> bool:
    return normalize(raw) in cities
```

Данные снаружи — из файла, из формы, из чужого API — всегда грязные: лишние
пробелы, случайный регистр, перевод строки в конце. Их чистят один раз на
входе, и дальше весь код работает с уже нормальным значением. Уровень
тренирует именно этот шаг.
