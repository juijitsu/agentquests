# Разбор · Как решить, шаг за шагом

## Шаг 1. Запустите заготовку как есть

Она работает и ошибается. Вердикт:

```
✓ вернулся текст: да
✗ меток совпало: 1 из 10
✗ первое расхождение: на метке '  dallas run 47 '
      ждали:   'DAL47'
      пришло:  '  d7 '
                ^
```

Обе строки показаны в кавычках специально. Пробелы и переводы строк на экране
не видно, а в кавычках видно край: `'  d7 '` начинается с двух пробелов и ими
же заканчивается. Каретка стоит там, где ответы разошлись: первый символ ещё
совпал (кавычка), а дальше пошло расхождение.

## Шаг 2. Поймите, почему совпала ровно одна метка

Десять меток, совпала одна. Это подсказка, а не случайность.

Заготовка режет `text` таким, каким он пришёл. Значит она попадёт в ответ
ровно тогда, когда метка **уже чистая и уже заглавными** — резать в этом
случае нечего, уборка не нужна.

Такая метка в наборе одна: `"OMAHA RUN 33"`. На всех остальных мешает либо
пробел по краям, либо строчные буквы, либо и то и другое.

Отсюда вывод: код режет правильно, а вот убирает — нет.

## Шаг 3. Найдите холостые строки

```python
def solve(text: str) -> str:
    text.strip()
    text.upper()
    return text[:3] + text[-2:]
```

Посмотрите на первые две строки: каждая состоит из одного вызова, и результат
никуда не идёт. Ни `=`, ни `return`, ни аргумент другого вызова.

`text.strip()` действительно посчитал чистую строку. И тут же её выбросил,
потому что забрать её было некому. `text` при этом не изменился — строки в
Python не меняются вовсе.

## Шаг 4. Поймайте результат в имя

```python
    clean = text.strip()
    code = clean.upper()
```

Теперь у каждой уборки есть адрес. `clean` — метка без краёв, `code` — она же
заглавными. Обратите внимание: во второй строке слева от точки стоит `clean`,
а не `text`. Если оставить `text`, вторая уборка снова возьмёт грязный
исходник, и половина работы пропадёт.

## Шаг 5. Режьте уже чистую строку

```python
    return code[:3] + code[-2:]
```

- `code[:3]` — три первых символа;
- `code[-2:]` — два последних;
- `+` между двумя кусками текста склеивает их, как на прошлом уровне.

Целиком:

```python
def solve(text: str) -> str:
    clean = text.strip()
    code = clean.upper()
    return code[:3] + code[-2:]
```

Три строки, и каждую можно проверить отдельно.

## Шаг 6. Запустите

```
✓ вернулся текст: да
✓ меток совпало: 10 из 10
✓ первое расхождение: все совпали
```

## Шаг 7. Если не совпало

**Совпала ровно одна метка** — результат уборки по-прежнему не пойман.
Проверьте, что перед `text.strip()` стоит `имя =`.

**Совпали не все, а ответы строчными** — `.upper()` вызван, но его результат
не пойман, либо срез идёт по `clean`, а не по `code`.

**В ответе видны пробелы** — режется `text`, а не `code`. Посмотрите, что
стоит в квадратных скобках в строке `return`.

**Совпали почти все, кроме одной** — скорее всего, вы вырезали пробелы не
только по краям. Внутри метки пробел значим: правило про три первых символа
означает буквально три первых символа очищенной строки, даже если один из них
пробел.

**`TypeError: ... is not subscriptable`** — у метода потерялись скобки:
написано `text.strip[:3]` вместо `text.strip()[:3]`.

**`AttributeError: 'str' object has no attribute ...`** — опечатка в имени
метода. Правильно: `strip`, `upper`.

**`IndexError`** — где-то стоит одиночный индекс вместо среза. `code[3]` может
не существовать, `code[:3]` существует всегда.

## Шаг 8. Проверьте себя

Не заглядывая: почему после `text.strip()` в `text` по-прежнему пробелы?
Если ответ приходит сразу — уровень усвоен, и на всех следующих уровнях эта
ловушка вас уже не поймает.
