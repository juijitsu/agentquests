# Теория · Число и текст, похожий на число

На прошлом уровне всё было текстом, и плюс склеивал. Здесь появляются числа —
и тот же плюс начинает означать другое.

---

## Переменная

**Что это.** Имя, за которым лежит значение.

```python
loaded = 1450
```

Слева имя, посередине знак равенства, справа значение. После этой строки слово
`loaded` можно писать вместо числа 1450 в любом месте.

**Зачем.** Чтобы посчитать в несколько шагов и каждому шагу дать понятное имя.
Сравните:

```python
return miles + " + 60 = " + str(int(miles) + 60)   # всё в одну строку

loaded = int(miles)                                 # то же самое, но видно,
total = loaded + 60                                 # что происходит
return miles + " + 60 = " + str(total)
```

Обе строки делают одинаковое. Вторая читается.

**Чего не делать.** Не путайте `=` и `==`. Одно равно — это «положи справа в
имя слева». Два равно — вопрос «равны ли», он понадобится на уровне про
условия.

**Что вы увидите, если написать имя, которого нет:**
`NameError: name 'loded' is not defined` — обычно это опечатка.

---

## Два разных вида значений

```python
1450      # число, с ним можно считать
"1450"    # текст из четырёх цифр, с ним считать нельзя
```

Выглядят похоже, ведут себя по-разному. Разница не в том, что написано, а в
кавычках вокруг.

**Как проверить, что перед вами.** Спросите питон:

```python
type(1450)      # <class 'int'>   целое число
type("1450")    # <class 'str'>   строка, то есть текст
```

`int` от integer, целое. `str` от string, строка.

---

## Плюс означает два разных действия

Это главное на уровне.

```python
1450 + 60         # 1510      числа складываются
"1450" + "60"     # "145060"  тексты склеиваются
```

Один и тот же знак. Питон смотрит не на знак, а на то, что по бокам от него.

**Что ломается, если по бокам разное.**

```python
"1450" + 60
```

Питон не догадывается, чего вы хотели: склеить или сложить. Он отказывается.

**Что вы увидите:** `TypeError: can only concatenate str (not "int") to str`.

Дословно: к строке можно приклеить только строку, а не целое.

**Чего не делать.** Прочитав это сообщение, новичок обычно ставит кавычки
вокруг числа: `"1450" + "60"`. Ошибка исчезает, и появляется другая,
беззвучная: получилось `"145060"` вместо `1510`. Программа не падает, ответ
неверный. Именно так устроена заготовка этого уровня.

---

## Перевод из одного вида в другой

**`int(текст)`** делает из текста число.

```python
int("1450")     # 1450
int("0")        # 0
```

**`str(число)`** делает из числа текст.

```python
str(1510)       # "1510"
```

**Зачем оба.** В задании пробег приходит текстом, а прибавить к нему надо
число — значит нужен `int`. Ответ собирается плюсом, а плюс между текстом и
числом не работает — значит сумму надо вернуть в текст через `str`.

**Что ломается у `int`.** Он принимает только цифры и ничего больше.

```python
int("1450 ")    # пробел внутри, ошибка
int("тысяча")   # буквы, ошибка
int("14.5")     # точка, ошибка: это не целое
```

**Что вы увидите:** `ValueError: invalid literal for int() with base 10`.
Дословно: для int() это не годится.

---

## Как выглядит правильный ход мысли

Задание требует одну строку, а в ней одно и то же значение встречается
**дважды и по-разному**:

```
"1450 + 60 = 1510"
 ────           ────
 текстом        числом
```

Слева пробег нужен ровно таким, каким пришёл — это уже текст, трогать не
надо. Справа нужна сумма, а сложить можно только числа.

Отсюда три шага: сделать из текста число, прибавить, вернуть результат в
текст.

---

## Что будет, если ошибиться

| Что вы увидите | Что случилось | Что делать |
|---|---|---|
| ответ вроде `1450 + 60 = 145060` | сложили тексты вместо чисел | `int(miles)` перед сложением |
| `TypeError: can only concatenate str` | склеиваете текст с числом | оберните число в `str()` |
| `TypeError: unsupported operand` | складываете число с текстом | приведите обе части к одному виду |
| `ValueError: invalid literal for int()` | в тексте не только цифры | уберите лишнее до `int()` |
| `вернулся текст: нет` | вернули число, а нужен текст | оберните ответ в `str()` |

---

## Чего не делать

- **Не ставить кавычки вокруг 60**, чтобы убрать `TypeError`. Ошибка уйдёт,
  ответ станет неверным молча.
- **Не переводить в число весь ответ.** `int("1450 + 60 = 1510")` не сработает:
  там не одни цифры.
- **Не менять `miles`.** Слева в ответе он нужен ровно таким, каким пришёл.

---

## Как это выглядит в настоящем коде

```python
def rate_line(miles: str, per_mile: float) -> str:
    total = int(miles) * per_mile
    return miles + " миль по " + str(per_mile) + " = " + str(total)
```

Та же тройка: перевести вход в число, посчитать, вернуть результат в текст.
