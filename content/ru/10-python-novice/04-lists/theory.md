# Теория · Список, порядок и место в нём

До сих пор у нас было одно значение за раз: текст, число. Здесь появляется
**список** — много значений под одним именем, выстроенных в ряд. И вместе с
ним появляется новое понятие: **место**. У значения в списке есть номер, а
номер зависит от порядка. Порядок сам собой не появляется.

Отсюда ловушка уровня: середина списка и середина по величине — это разные
вещи, пока список не выстроен.

---

## Что такое список

```python
quotes = [1200, 900, 1450]
```

Квадратные скобки, значения через запятую. Это одно значение — список, — но
внутри у него три числа, и они идут в определённом порядке.

**Зачем.** Ставок может прийти три, пять или сорок. Заводить под каждую своё
имя невозможно. Список позволяет держать их вместе и работать с ними как с
одним предметом.

**Что можно класть.** Что угодно, в том числе разное сразу:

```python
[1200, 900, 1450]              # числа
["dallas", "memphis"]          # строки
[]                             # пустой список — это тоже список
```

На практике в один список кладут однородное: все ставки, все города. Смесь
чисел и строк почти всегда означает, что данные пришли грязными.

**Сколько элементов.** Та же функция `len`, что считала длину строки:

```python
len([1200, 900, 1450])    # 3
len([])                   # 0
```

---

## Место элемента: индекс

Как и у строки, у элементов списка есть номера, и начинаются они с нуля.

```
список:  [1200,  900, 1450]
индекс:      0     1     2
с конца:    -3    -2    -1
```

```python
quotes = [1200, 900, 1450]
quotes[0]     # 1200 — первый
quotes[1]     # 900
quotes[-1]    # 1450 — последний
```

**Почему с нуля.** Индекс — это не «который по счёту», а «на сколько шагов
отступить от начала». От начала до первого элемента отступать не надо, отсюда
ноль. Ту же логику мы видели у срезов на прошлом уровне: `code[:3]` — три шага
от начала.

**Что ломается.** Номер за пределами списка:

```python
quotes[3]     # IndexError: list index out of range
```

Три элемента — номера 0, 1, 2. Тройки нет. Последний элемент всегда имеет
номер `len(quotes) - 1`, и это самая частая причина ошибки «на единицу».

## Список — изменяемый, и это отличие от строки

На прошлом уровне мы выяснили: строку изменить нельзя, любой метод отдаёт
новую. **Со списком всё наоборот** — его можно менять на месте.

```python
quotes = [1200, 900, 1450]
quotes[1] = 1000
print(quotes)          # [1200, 1000, 1450] — тот же список, другое содержимое
quotes.append(700)
print(quotes)          # [1200, 1000, 1450, 700]
```

`append` дописывает элемент в конец и **ничего не возвращает** — он меняет сам
список. Это ровно то исключение, о котором говорилось на прошлом уровне: у
строк таких методов нет, у списков есть.

**Почему языки так делают.** Список обычно большой и живёт долго: в него
дописывают, из него удаляют. Каждый раз копировать его целиком было бы дорого.
Строка же чаще всего мелкая и служит значением, а неизменяемость делает её
безопасной.

**Чем это опасно.** Изменяемый список, переданный в функцию, — это тот же
самый список, а не копия. Если функция его переставит, снаружи он тоже
окажется переставленным. На этом уровне проверка передаёт вашей функции копию
именно поэтому.

## Два способа выстроить список по порядку

Здесь язык предлагает два инструмента, и путать их — классическая ошибка.

### `sorted(список)` — функция, отдаёт новый список

```python
quotes = [1200, 900, 1450]
in_order = sorted(quotes)
print(in_order)    # [900, 1200, 1450] — новый список
print(quotes)      # [1200, 900, 1450] — старый не тронут
```

Работает как `len()` или `str()`: имя, скобки, аргумент внутри. Результат надо
поймать в имя — как и на прошлом уровне.

### `список.sort()` — метод, переставляет на месте

```python
quotes = [1200, 900, 1450]
quotes.sort()
print(quotes)      # [900, 1200, 1450] — тот же список, уже по порядку
```

Метод не создаёт ничего нового. Он переставляет элементы прямо в списке и
**возвращает None** — то есть «ничего».

**Вот здесь и стоит капкан:**

```python
in_order = quotes.sort()   # in_order стал None
len(in_order)              # TypeError: object of type 'NoneType' has no len()
```

По привычке с прошлого уровня хочется поймать результат в имя. Но ловить
нечего: `sort()` уже всё сделал, а вернул пустоту.

**Как запомнить разницу.**

| | `sorted(quotes)` | `quotes.sort()` |
|---|---|---|
| это | функция | метод списка |
| старый список | не трогает | переставляет |
| возвращает | новый список | `None` |
| результат ловить | обязательно | нечего ловить |
| работает с | списком, строкой, чем угодно перебираемым | только со списком |

**Что выбрать.** Если исходный порядок ещё нужен — только `sorted()`. Если
не нужен и список большой — `sort()` дешевле, он не копирует. В эталоне этого
уровня взят `sorted()`: он нагляднее и не зависит от того, чья это копия.

**По убыванию:** `sorted(quotes, reverse=True)` или `quotes.sort(reverse=True)`.

## Середина: деление нацело

Номер середины списка — это его длина, поделённая пополам. Но индекс обязан
быть целым числом, а обычное деление даёт дробь:

```python
len([1200, 900, 1450]) / 2     # 1.5  — дробь
len([1200, 900, 1450]) // 2    # 1    — целое
```

Две косые черты — **деление нацело**: дробная часть отбрасывается.

```python
quotes[1.5]    # TypeError: list indices must be integers or slices, not float
quotes[1]      # 900
```

Для нечётной длины `len // 2` всегда попадает ровно в середину:

| длина | индексы | `len // 2` | середина |
|---|---|---|---|
| 1 | 0 | 0 | 0 ✓ |
| 3 | 0 1 2 | 1 | 1 ✓ |
| 5 | 0 1 2 3 4 | 2 | 2 ✓ |
| 7 | 0 … 6 | 3 | 3 ✓ |

Слева от середины столько же элементов, сколько справа. Для чётной длины
середины как одного элемента не существует вовсе — поэтому в задании
количество ставок всегда нечётное.

---

## Почему середина неотсортированного списка ничего не значит

```
пришло:      [1200,  900, 1450]      элемент посередине = 900
по порядку:  [ 900, 1200, 1450]      элемент посередине = 1200
```

Ставки приходят в том порядке, в каком перевозчики нажали «отправить». Этот
порядок ничего не говорит о деньгах. Взять из такого списка средний по счёту
элемент — всё равно что спросить «какая ставка пришла третьей»: ответ будет,
но смысла в нём нет.

Иногда такой ответ случайно совпадает с правильным — когда середина и так
оказалась на своём месте. Именно это и делает ошибку опасной: на части данных
код «работает».

---

## Зачем вообще средняя по счёту, а не средняя по деньгам

Это два разных вопроса, и они дают разные ответы.

```python
quotes = [900, 950, 1000, 3800, 4000]
sum(quotes) // len(quotes)   # 2130 — среднее арифметическое
sorted(quotes)[2]            # 1000 — та, что посередине
```

Среднее тянут вверх две завышенные ставки. Средняя по счёту говорит другое:
половина перевозчиков просит меньше тысячи, половина больше. Для решения
«сколько это стоит на рынке» вторая цифра честнее.

Значение посередине называют **медианой**. Ею пользуются везде, где отдельные
выбросы способны испортить картину: зарплаты, цены на жильё, время ответа
сервиса.

---

## Что ломается и как это выглядит

| Что вы увидите | Что произошло | Что делать |
|---|---|---|
| совпали не все наборы | список не выстроен по возрастанию | `in_order = sorted(quotes)` |
| `TypeError: object of type 'NoneType' has no len()` | результат `sort()` пойман в имя | `sort()` возвращает `None`, ловить нечего |
| `TypeError: 'NoneType' object is not subscriptable` | то же самое, но с индексом | берите сам список, а не результат `sort()` |
| `AttributeError: 'list' object has no attribute 'sorted'` | `sorted` вызван как метод | `sorted(quotes)`, а метод — `quotes.sort()` |
| `TypeError: list indices must be integers` | индекс получился дробным | `//` вместо `/` |
| `IndexError: list index out of range` | номер за пределами списка | последний номер — `len(quotes) - 1` |
| `TypeError: '<' not supported between instances of ...` | в списке значения разных типов | сортировать можно только сравнимое |

---

## Чего делать не надо в этой теме

- **Не берите элемент по номеру, не убедившись в порядке.** Номер осмыслен
  только вместе с порядком.
- **Не ловите результат `sort()`.** Там `None`. Это зеркало прошлого уровня:
  там результат обязательно ловили, здесь ловить нечего.
- **Не делите длину одной косой чертой.** `len(quotes) / 2` даёт дробь, а
  индекс обязан быть целым.
- **Не считайте последним элементом `quotes[len(quotes)]`.** Последний —
  `quotes[len(quotes) - 1]` или просто `quotes[-1]`.
- **Не сортируйте на месте чужой список,** если его порядок кому-то ещё нужен:
  `sort()` меняет тот самый список, который вам передали.

## Как это выглядит в настоящем коде

```python
def median(values: list[int]) -> float:
    """Значение посередине. Для чётной длины — среднее двух центральных."""
    in_order = sorted(values)
    middle = len(in_order) // 2
    if len(in_order) % 2 == 1:
        return in_order[middle]
    return (in_order[middle - 1] + in_order[middle]) / 2
```

Первые две строки — ровно то, что делает эталон этого уровня. Дальше идёт
случай чётной длины: тогда середины как элемента нет, и берут среднее двух
соседних. В задании такого случая нет специально — условие про нечётное
количество снимает его, чтобы уровень остался про порядок, а не про ветвление.
Ветвление разберём на уровне про условия.
