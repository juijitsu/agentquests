# Разбор · Как решить, шаг за шагом

## Шаг 1. Запустите заготовку как есть

Она работает и ошибается. Вердикт:

```
✓ вернулось число: да
✗ наборов совпало: 2 из 9
✗ первое расхождение: на ставках [1200, 900, 1450]
      по порядку: [900, 1200, 1450]
      ждали:   1200
      пришло:  900
```

Вердикт печатает две строки подряд: набор, каким он пришёл, и он же по
порядку. В этом весь уровень. Посередине пришедшего набора стоит `900`,
посередине выстроенного — `1200`. Это разные ставки.

## Шаг 2. Поймите, почему совпали ровно два набора

Девять наборов, совпало два. Оба — не случайность, и у каждого своя причина.

**Первый:** `[700, 1100, 950, 800, 1300]`. Здесь `950` уже стоит на своём
месте: две ставки меньше, две больше. Перевозчики прислали их в таком порядке
случайно, но середина сошлась.

**Второй:** `[1750]`. Одна ставка. Сортировать нечего, середина всегда она
сама. Такой набор пройдёт при любом подходе.

Оба случая говорят одно: код не «иногда работает», код не делает нужного
вовсе, а совпадения приходят от данных.

## Шаг 3. Посмотрите, что именно берёт заготовка

```python
def solve(quotes: list[int]) -> int:
    middle = len(quotes) // 2
    return quotes[middle]
```

Строки честные: `len(quotes) // 2` действительно даёт номер середины, а
`quotes[middle]` действительно берёт элемент по этому номеру.

Не хватает шага между ними. Номер середины осмыслен только тогда, когда
список выстроен по возрастанию. Список от перевозчиков не выстроен: он идёт
в том порядке, в каком нажали «отправить».

## Шаг 4. Выстройте ставки по порядку

```python
    in_order = sorted(quotes)
```

`sorted()` возвращает **новый** список, выстроенный по возрастанию. Исходный
`quotes` при этом остаётся как был — он нам больше не понадобится, но знать
это важно.

**Не пишите так:**

```python
    in_order = quotes.sort()    # in_order станет None
```

`sort()` переставляет список на месте и не возвращает ничего. Если хочется
именно его, то без присваивания:

```python
    quotes.sort()
    middle = len(quotes) // 2
    return quotes[middle]
```

Оба варианта верны. В разборе дальше идёт первый.

## Шаг 5. Считайте середину по выстроенному списку

```python
    middle = len(in_order) // 2
    return in_order[middle]
```

Обратите внимание: и длина, и элемент берутся из `in_order`. Длина у обоих
списков одинаковая, так что `len(quotes)` тут не ошибка, — а вот
`quotes[middle]` в последней строке вернул бы всё то же неверное значение.
Проще держаться одного имени и не думать об этом.

Целиком:

```python
def solve(quotes: list[int]) -> int:
    in_order = sorted(quotes)
    middle = len(in_order) // 2
    return in_order[middle]
```

## Шаг 6. Запустите

```
✓ вернулось число: да
✓ наборов совпало: 9 из 9
✓ первое расхождение: все совпали
```

## Шаг 7. Если не совпало

**Совпало по-прежнему два набора** — сортировка либо не применена, либо
применена, а элемент берётся из старого списка. Проверьте, что в последней
строке в квадратных скобках стоит `in_order`, а не `quotes`.

**`TypeError: object of type 'NoneType' has no len()`** — написано
`in_order = quotes.sort()`. Метод `sort()` возвращает `None`. Возьмите
`sorted(quotes)` или уберите присваивание.

**`TypeError: 'NoneType' object is not subscriptable`** — то же самое, только
ошибка вылезла на строке с индексом.

**`AttributeError: 'list' object has no attribute 'sorted'`** — написано
`quotes.sorted()`. `sorted` — функция: `sorted(quotes)`. Метод у списка
называется `sort`.

**`TypeError: list indices must be integers`** — деление одной косой чертой
дало дробь. Нужно `//`.

**`IndexError: list index out of range`** — номер вышел за пределы. При
делении нацело это обычно означает, что к середине что-то прибавили.

## Шаг 8. Проверьте себя

Не заглядывая: почему `quotes[len(quotes) // 2]` верен для
`[700, 1100, 950, 800, 1300]` и неверен для `[1200, 900, 1450]`? Если ответ
приходит сразу, значит связка «номер имеет смысл только при известном
порядке» усвоена — а это половина всей работы со списками.
