# Метод · Порядок проверок в цикле

Ошибка этого уровня живёт в одной строке — в том, **в каком порядке** цикл
разбирает ответ модели.

Ответ может содержать и текст, и просьбу вызвать инструмент **одновременно**.
Если проверить текст первым и сразу выйти — просьба останется невыполненной, а
наружу уйдёт отчёт о несделанной работе.

Правильный порядок:

**Шаг 1. Сначала инструменты.** Есть `tool_calls` — выполнить все, вернуть
результаты в `messages`, идти на следующую итерацию. Текст при этом
игнорируется: он промежуточный.

**Шаг 2. Текст — только когда просьб больше нет.** Пустой `tool_calls` означает,
что модель закончила. Вот теперь её текст и есть ответ.

```python
if response.tool_calls:          # сначала это
    ...выполнить и продолжить...
return response.text, step       # и только потом это
```

**Шаг 3. Проверять по последствиям.** Убедиться, что действие произошло, можно
только по следу: запись в журнале, файл на диске, строка в базе. Слова агента
доказательством не являются.
