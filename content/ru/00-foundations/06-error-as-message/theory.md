# Теория · Ошибка как сообщение

На прошлом уровне вы научились не ронять процесс. Теперь вопрос тоньше: **кому
адресован отказ**.

Отказы бывают двух видов, и путать их дорого.

**Отказ для человека.** Кончился лимит шагов, недоступен провайдер, нет прав.
Агент сделать с этим ничего не может — надо, чтобы вмешался человек.

**Отказ для модели.** Неверное значение аргумента, опечатка в названии, не тот
формат. Модель может это исправить — если узнает.

Разница практическая. Первый отказ уходит наружу и заканчивает работу. Второй
возвращается **в цикл** и работу продолжает.

## Что происходит с исключением

Инструмент бросил `ValueError`. Дальше три сценария.

**Не поймали.** Процесс упал, пользователь видит стектрейс. Это уровень 05.

**Поймали и вернули человеку.** Процесс жив, пользователь получил вежливое «не
удалось». Выглядит прилично — и всё равно неправильно: агент сдался там, где
мог исправиться за один лишний шаг.

**Поймали и вернули модели.** Текст ошибки кладётся в `messages` ролью `tool` —
как обычный результат вызова. На следующей итерации модель его читает и пробует
снова, уже верно.

Только третий вариант делает агента агентом.

## Почему текст ошибки важнее самого факта

Модель исправится, только если поймёт, что не так. Сообщение «неверный аргумент»
не помогает никому. Сообщение

> перехода 'Loredo' не существует. Доступны: Laredo, El Paso, Otay Mesa

содержит и диагноз, и список того, из чего выбирать. **Перечисляйте допустимые
значения в тексте ошибки** — это самое дешёвое, что можно сделать для
самоисправления.
