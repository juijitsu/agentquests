# Метод · Считать внутри вида

**Шаг 1. Прогоните набор, как раньше.** Ничего не меняется: те же случаи, та же
проверка.

**Шаг 2. Соберите виды из самого набора.**

```python
for kind in {c["kind"] for c in CASES}:
```

Не выписывайте список видов руками: добавится новый — вы про него забудете, а
метрика об этом не скажет.

**Шаг 3. Считайте долю внутри вида, а не долю вида в общем.**

```python
same = [c for c in CASES if c["kind"] == kind]
hit = [c for c in same if c in passed]
by_kind[kind] = round(100 * len(hit) / len(same))
```

Знаменатель — размер вида. Это и есть вся разница между «половина перегрузов
неверна» и «перегрузы дают двадцать процентов всех ошибок».

**Шаг 4. Оставьте общий процент.** Он не мешает и полезен для динамики.
Существенно, чтобы он был не единственным.

заново.** Если ваша главная метрика выросла, она измеряет состав набора, а не
работу системы.
