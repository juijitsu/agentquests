# Теория · Шаг выполнен ≠ задача выполнена

На прошлом уровне план был известен заранее: четыре звена, пройти все, сложить.
Такие задачи удобны и редки.

Чаще плана нет, потому что его нельзя составить. Диспетчерская отдаёт только
следующий пункт: доедешь до Далласа — узнаешь, что после Далласа. Маршрут
выясняется по дороге, и заранее неизвестно даже, сколько будет шагов.

## Откуда берётся ошибка

Вспомните условие выхода из цикла, которое вы писали в фундаменте:

```python
if not response.tool_calls:
    return response.text, step
```

Оно означает «модель перестала просить инструменты». В простой задаче это
совпадало с «задача решена» — потому что задача была в один шаг.

В многошаговой не совпадает. Модель отчитывается о **шаге**: «доехали до
Далласа». Инструменты ей на этот момент не нужны, `tool_calls` пуст, цикл
выходит — и наружу уходит промежуточный результат, выданный за окончательный.

**Условие выхода было техническим. Задача требует смыслового.**

## Кто решает, что работа закончена

Не модель. Она видит один шаг и честно про него отчитывается — большего от неё
и не просили.

Решает ваш код, потому что цель сформулирована в нём:

```python
if GOAL in response.text:
    return response.text, step
```

Это и есть разница между агентом, который выполняет шаги, и агентом, который
решает задачу.

## Что делать, если задача не закончена

Продолжить цикл, сообщив модели новое положение дел. Модель без памяти и без
контекста снова увидит только последний шаг — значит этот шаг надо ей дать.
Отсюда добавление в историю: «доехали до Далласа, куда дальше».

Цикл продолжается ровно до тех пор, пока цель не достигнута или не кончились
шаги. Ограничитель здесь особенно важен: в задаче с неизвестной длиной легко
уехать в бесконечность.
