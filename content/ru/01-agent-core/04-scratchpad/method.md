# Метод · Три претендента на окно

На уровне 03 в окне было двое: условие и хвост. Теперь трое.

**Шаг 1. Посчитайте места.** Окно фиксировано. Условие занимает одно, блокнот —
столько, сколько в нём записей, хвост получает остаток:

```python
tail = WINDOW - 1 - len(notes)
```

Это не формальность: если посчитать неверно, окно переполнится ровно на одно
сообщение, и модель откажется работать.

**Шаг 2. Соберите окно по приоритету.** Порядок отражает важность — то, что
нужно всегда, идёт первым:

```python
return [условие] + заметки + история[-tail:]
```

**Шаг 3. Следите за размером блокнота.** Он растёт, хвост сжимается. Если
записей становится много, значит агент пишет лишнее — либо описание инструмента
`write_note` слишком расплывчато, либо в задаче действительно нужен более умный
отбор.
