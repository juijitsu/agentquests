# Method · How to write a description that gets picked

Four steps. They work for any tool.

**Step 1. Name it with a domain verb.** Not `get_data` but `check_border_status`.
If a logistics person would not say it that way, the tool's boundary is drawn
wrong, and no description will save that.

**Step 2. Write when to use it.** The first sentence of the description answers
"in what situation do I call this", not "what is inside".

> Shows the queue and wait time at a border crossing.

**Step 3. List the allowed values.** In the description text itself, not only in
the schema.

> Allowed values for crossing: Laredo, El Paso, Otay Mesa.

**Step 4. Check it against its neighbour.** Take the second, similar tool and ask
yourself: by which word will the model tell them apart? If there is no such word,
add one.

---

Descriptions are tested with a request, not by reading. Phrase the question the
way a customer would, **without naming the tool**, and see what the agent picks.
